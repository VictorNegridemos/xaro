3. **Migration guard is slightly stricter than plan 3.5**: `ALTER TABLE … ADD CONSTRAINT` must be a foreign key between the four new tables; only one statement is allowed per breakpoint; a function body may not contain `drop/truncate/alter/delete/insert/update/grant/revoke/execute/copy`. The three approved files pass.
4. **Extra files not named in the plan**: `scripts/lib/legacy.ts`, `scripts/lib/restore-sql.ts`, `scripts/lib/copy-legacy.ts` (shared code of the four DB scripts), `scripts/sql/search-smoke.sql` (the 4.2 statement for the dry run's smoke test; the Search stream builds its own `src/lib/search/sql.ts`), `scripts/db-status.ts` (read-only overview used for the `SELECT type, count(*)` check; no npm script).
